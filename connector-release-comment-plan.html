Implementation plan

Connector stable-tag collaboration comments

Add the historical release comment behavior to the Connector Master reusable workflow. After a successful stable connector release, write the release comment to every referenced collaboration task through the task batch API using the release metadata and quality-gate result.

Plan status Implemented; canary pending
Workflow scope Connector Master Workflow
Release scope Stable tags only
Failure policy Release remains non-blocking

Confirmed behavior

  • Run only after the selected SDK or Legacy connector pipeline succeeds completely.
  • Run only for stable connector tags; skip branches, pull requests, forks, and prerelease tags.
  • Use PATCH api/tasks/batch to write the release comment to each task, using task IDs from the released version history.
  • Use the released connector version, branch comment, change entries, task references, and quality-gate result to build the comment.
  • If comment creation fails, report the failure clearly but do not fail or block the connector release.
  • Repeated execution must safely reapply the same release comment without creating duplicate comment resources.

Known API findings

Important: the task batch endpoint is the approved API surface for this feature. The task IDs must be read from the matching release entry in the connector version history before the batch update is built.
API surface What is known Plan decision
PATCH api/tasks/batch Updates task fields in batch, including DCPTask.Comment, which the API model describes as the task's latest comment. Use it with the task ID, current task version, and formatted release comment. Read the current version before patching.
POST api/comments Creates a Comment resource and returns 201 Created. The documented body includes ssgId, commentTypeId, and commentText. Not used for this feature; the approved contract is the task batch endpoint.
Connector version history The released version entry contains the collaboration task references used to associate the release comment with tasks. Read the matching version-history entry and collect/deduplicate its task IDs before the API update.

Reference repositories for API conventions: collaboration-mcp-server and skyline-bruno-api-collections.

Acceptance criteria

  • A successful stable connector tag produces the exact release comment on every referenced collaboration task.
  • The release comment is written through PATCH api/tasks/batch using task IDs taken from the matching version-history entry.
  • Prerelease tags, branches, and pull requests never create comments.
  • The compliance statement is present only after the selected connector pipeline has passed its quality gates.
  • Comment API failures are visible and actionable but do not block the release.
  • Retries are safe and do not create duplicate comment resources or malformed task metadata.
  • No credentials are exposed in workflow inputs, command lines, logs, or artifacts.
  • Offline tests, composite smoke tests, workflow validation, and downstream coverage pass.
